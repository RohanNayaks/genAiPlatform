DELIVERABLE 1: JAILBREAK DETECTION
File: guards/jailbreak.py
Service: services/guard_service.py

The JailbreakGuard (and its SOLID-compliant twin JailbreakGuardService)
provides an early-exit security layer that intercepts malicious inputs
before any processing occurs.

Detection Strategy — Two-Layer Approach:

  Layer 1: Banned Keyword Matching (16 keywords, case-insensitive)
  ┌────────────────────────────────────────────────────────────────┐
  │  "ignore previous instructions"   "ignore all instructions"   │
  │  "disregard your"                 "forget your instructions"  │
  │  "you are now"                    "act as"                    │
  │  "pretend you are"                "pretend to be"             │
  │  "roleplay as"                    "jailbreak"                 │
  │  "bypass"                         "override instructions"     │
  │  "do anything now"                "dan mode"                  │
  │  "evil mode"                      "unrestricted mode"         │
  └────────────────────────────────────────────────────────────────┘

  Layer 2: Structural Injection Pattern Detection (7 regex patterns)
  ┌────────────────────────────────────────────────────────────────┐
  │  r"system\s*:\s*you"          → system: you are ...           │
  │  r"<\s*system\s*>"            → <system> tags                 │
  │  r"\[system\]"                → [system] markers              │
  │  r"###\s*instruction"         → ### Instruction: ...          │
  │  r"---\s*new\s*prompt"        → --- new prompt ---            │
  │  r"ignore\s+.{0,30}(above|   → ignore X instructions         │
  │    prior|previous|preceding)" │                               │
  │  r"prompt\s*injection"        → prompt injection              │
  └────────────────────────────────────────────────────────────────┘

Method Signature:
  is_jailbreak(text: str) -> bool
  Returns True immediately on first match (early exit).
  All checks are case-insensitive (text.lower() applied).

Integration Point:
  - Router (routers/response_router.py) calls guard.is_jailbreak()
    as the FIRST check on every incoming request.
  - On detection: raises HTTP 400 with message
    "Request rejected: potential jailbreak detected"
  - Guard check runs BEFORE "generate" keyword check and cache access.

SOLID Design:
  - BaseGuard ABC defines the is_jailbreak() interface
  - JailbreakGuardService implements BaseGuard
  - Router depends on BaseGuard abstraction via FastAPI Depends()

DELIVERABLE 2: ENHANCED DATA MASKING — GLiNER
File: guards/GlinerGuardial.py
Service: services/masking_service.py

GLiNERGuardial is a drop-in replacement for the Phase 1 DistilBERT
masker (InputGuardial), providing zero-shot entity recognition without
task-specific fine-tuning.

Model: urchade/gliner_mediumv2.1 (HuggingFace)
Type:  Zero-shot Generalist Named Entity Recognition (GLiNER)

Default Entity Labels (8 categories):
  person, email, phone number, address,
  organization, date, credit card, ssn

Processing Pipeline:
  Text Input
    → GLiNER.from_pretrained("urchade/gliner_mediumv2.1")
    → model.predict_entities(text, labels, threshold=0.5)
    → create_entity_map(): {entity_text → LABEL_UPPERCASE}
    → replace_entities(): text.replace(entity, "[LABEL]")
    → result_data (masked text)

Output Format:
  Entities replaced as [LABEL] — e.g., "John" → "[PERSON]"
  Consistent with Phase 1 InputGuardial output format.

Key Differences vs Phase 1 DistilBERT Masker:
  ┌──────────────────┬─────────────────────────┬──────────────────────┐
  │ Aspect           │ Phase 1 (DistilBERT)     │ Phase 2 (GLiNER)     │
  ├──────────────────┼─────────────────────────┼──────────────────────┤
  │ Model            │ Isotonic/distilbert_     │ urchade/gliner_      │
  │                  │ finetuned_ai4privacy_v2  │ mediumv2.1           │
  ├──────────────────┼─────────────────────────┼──────────────────────┤
  │ Approach         │ Fine-tuned classification│ Zero-shot NER        │
  ├──────────────────┼─────────────────────────┼──────────────────────┤
  │ Output keys      │ start, end, entity_group │ text, label, score   │
  ├──────────────────┼─────────────────────────┼──────────────────────┤
  │ Threshold        │ Model default            │ Configurable (0.5)   │
  ├──────────────────┼─────────────────────────┼──────────────────────┤
  │ Entity types     │ Fixed (AI4Privacy set)   │ Customizable labels  │
  └──────────────────┴─────────────────────────┴──────────────────────┘

Masking Strategy Selection (MaskingService):
  POST body field: "masking": "gliner"  → uses GLiNERGuardial
  POST body field: "masking": "default" → uses InputGuardial (Phase 1)
  POST body field: omitted              → defaults to "default"

DELIVERABLE 3: SOLID SERVICE LAYER REFACTOR
Directory: services/

Phase 2 introduces a full service layer applying all five SOLID
principles to replace the monolithic Phase 1 class hierarchy.

  guard_service.py   — JailbreakGuardService (BaseGuard ABC)
  masking_service.py — MaskingService + BaseMasker ABC
                       DistilBertMasker / GlinerMasker
  template_service.py— TemplateService (builds LangChain prompts)
  model_service.py   — ModelService + BaseModelProvider ABC
                       Phi3 / OpenAI / Claude / Gemini providers
  cache_service.py   — CacheService (Redis with graceful fallback)

SOLID Principle Mapping:
  S — Single Responsibility
      Each service class has exactly one job (guard, mask, template,
      model-route, cache). No class crosses concerns.

  O — Open/Closed
      ModelService._providers dict and MaskingService._maskers dict
      allow new models/maskers to be registered without modifying
      existing service code.

  L — Liskov Substitution
      DistilBertMasker and GlinerMasker are interchangeable through
      BaseMasker. All four model providers are interchangeable via
      BaseModelProvider. Callers need not know which concrete class
      they receive.

  I — Interface Segregation
      BaseGuard exposes only is_jailbreak().
      BaseMasker exposes only mask().
      BaseModelProvider exposes only generate().
      Each interface is minimal and focused.

  D — Dependency Inversion
      TemplateService receives MaskingService via constructor injection.
      CacheService receives TemplateService and ModelService via
      constructor injection. Router receives services via FastAPI
      Depends() — no hard imports of concrete classes in consumers.

DELIVERABLE 4: FASTAPI ROUTER & ENDPOINT CHANGES
File: routers/response_router.py
Main: main.py (simplified — now just mounts the router)

Phase 2 API Endpoint:

  POST /getResponse

  Request Body (JSON):
  {
    "text":       string  (required, min_length=1)
    "model":      string  (required: "phi3"|"openai"|"claude"|"gemini")
    "masking":    string  (optional: "gliner"|"default", default=null)
    "is_masking": boolean (optional, default=false)
  }

  Response (200 OK):
  {
    "response": string
  }

  Error Responses:
    400 Bad Request  → Jailbreak detected in input text
    500 Internal     → Unexpected processing error

  Request Processing Flow:
    ┌─────────────────────────────────────────────────────────┐
    │  POST /getResponse                                      │
    │     ↓                                                   │
    │  JailbreakGuardService.is_jailbreak(text)               │
    │     ├─ True  → HTTP 400 (rejected)                      │
    │     └─ False → ↓                                        │
    │  "generate" in text.lower()?                            │
    │     ├─ Yes → CacheService.get_response(                 │
    │     │          text, model, is_masking, masking)         │
    │     │          ↓                                        │
    │     │       Redis cache check                           │
    │     │          ├─ Hit  → return cached string           │
    │     │          └─ Miss → TemplateService.build()        │
    │     │                    → ModelService.generate()      │
    │     │                    → Redis.set() + return         │
    │     └─ No  → "This is the standard response"            │
    └─────────────────────────────────────────────────────────┘

Changes from Phase 1:
  - Endpoint changed from GET to POST
  - Jailbreak guard check added as first step
  - Masking strategy selectable per request ("gliner" / "default")
  - is_masking flag enables/disables PII masking
  - Router modularised into routers/response_router.py
  - main.py reduced to app setup + router mount only
